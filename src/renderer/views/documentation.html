Documentación y Guía de Uso

  1. Paso 1: Configurar la Aplicación en Marketing Cloud
    • Se deberá crear siempre la app en la BU PADRE y dar permisos a los usuarios. Los permisos se dan en el propio paquete que se ha creado en la pestaña ACCESS
    • Si se quiere usar en otras BUs, se debe dar permiso a cada BU y establecer una conexción por cada BU.
    • Ve a Setup → Apps → Installed Packages.
    • Crea un paquete de tipo Web App llamado MC API Helper.
    • En Redirect URI pon lo siguiente: https://127.0.0.1:8443/callback.
    • Pon los siguientes permisos:
      • Email: Read, Write
      • Automations: Read, Write, Execute
      • Journeys: Read, Write, Activate/Stop/Pause/Resume/Send/Schedule, Delete
      • Audiences: Read, Write
      • List and Subscribers: Read, Write
      • Data Extensions: Read, Write
      • Documents and Images: Read
      • Saved Content: Read
      • File Locations: Read
      • Users: Read
  2. Paso 2: Configurar un Cliente en esta App
    • Ve a Configuración de APIs e introduce los datos del paquete.
    • Pulsa "Login" para autenticarte vía browser.
    • Se levantará una ventana con el login de Marketing Cloud. Pon tus credenciales
    • Si da algún problema, vuelve a probarlo porque puntualmente MC puede no gestionar bien la conexión. Si sigue fallando, revisa que el usuario tiene permiso en la app del Paso 1

    Panel de configuración Base
    Selector de carpetas
    Panel de configuración Sendable

    Para configurar los campos se debe ir a la vista Configuración de Campos.

    En esta vista se puede:

    • Importar un documento con los campos, por ejemplo cuando los copiamos del modelo de datos de Salesforce. Para ello solo se debe pegar el listado de campos e indicar el tipo de separador.

    • Eliminar filas. Para ello seleccionando una fila, aparecerá una x a la derecha de la fila para poder eliminarla
    • Ordenar filas. Seleccionando una fila y usando las flechas, se puede ordenar la tabla. Esto es interesante sobre todo cuando queremos crear una copia de una tabla existente pero con un orden correcto, por ejemplo manteniendo los identificadores al principio. Contenidos

  • Contenidos

    Esta vista permite descargar todos los contenidos de la instancia para poder hacer búsquedas sobre ellos. En este caso Marketing Cloud no pone una forma fácil de obtenerlo así que es necesario hacer algun paso en el propio navegador para obtener lo contenidos.

El buscador filtrará los contenidos que contengan la cadena de texto. Aunque no se muestre, también busca en el cuerpo de los emails y se puede utilizar por ejemplo para saber qué mails utilizan una plantilla (buscando por el nombre de la misma).

Automatismos

  • Gestión de Automatismos

    Esta vista muestra todos los automatismos de la instancia en una tabla paginada con los siguientes datos: Nombre, Última Ejecución, Próxima Ejecución, Estado y las Notificaciones configuradas para errores y ejecuciones.

    Se puede filtrar por nombre (soporta múltiples valores separados por , ; o |) y por estado. Las columnas son ordenables haciendo clic en la cabecera.

    Botones disponibles:

    • Refrescar — Recarga los datos desde la API.
    • Analizar (requiere selección de 1) — Abre la vista de análisis detallado del automatismo seleccionado.
    • Cargar Notificaciones — Obtiene los emails de alerta configurados en cada automatismo y los muestra en la tabla.
    • Exportar — Descarga un CSV con los datos visibles (respetando los filtros activos).
    • Activar (requiere selección) — Activa automatismos que están parados o pausados.
    • Ejecutar (requiere selección) — Lanza una ejecución manual inmediata.
    • Parar (requiere selección) — Detiene automatismos en ejecución o programados.
    • Clonar (requiere selección de 1) — Navega al clonador selectivo de ese automatismo.

    Los botones de acción (Activar, Ejecutar, Parar) solo se habilitan cuando los automatismos seleccionados tienen un estado compatible con la acción. Si se seleccionan varios con estados distintos, los botones quedan deshabilitados.

  • Clonador de Automatismos

    Accesible desde la vista de Automatismos seleccionando uno y pulsando Clonar. Permite duplicar un automatismo de forma selectiva: se elige qué actividades clonar y cuáles reutilizar.

    Configuración disponible:

    • Nombre Destino — Nombre del nuevo automatismo (editable).
    • Carpeta Destino — Por defecto se usa la misma carpeta del original; se puede cambiar con el buscador de carpetas.
    • Por cada actividad del automatismo se puede indicar si clonarla o reutilizar la original, y se puede cambiar el nombre y la Data Extension de destino.
    • Se puede establecer una carpeta de DEs por defecto para que todas las DEs clonadas se guarden ahí sin tener que configurarlas una a una.

    El proceso crea primero las DEs de destino (si es necesario), luego las actividades y finalmente el automatismo completo con todos sus pasos.

Journeys

  • Gestión de Journeys

    Esta vista muestra todos los journeys de la instancia en una tabla paginada. Cada fila incluye: Nombre, Tipo, Subtipo, Estado, Data Extension de entrada, versiones y, si se han cargado, las comunicaciones (Emails, SMS, Push, WhatsApp) usadas en cada journey.

    Filtros disponibles: por nombre, tipo, subtipo, estado, Data Extension de entrada y campos de entrada. El botón ☐ Comunicaciones activa un filtro adicional para mostrar solo journeys que tienen comunicaciones cargadas.

    Botones disponibles:

    • Refrescar — Recarga los datos desde la API.
    • Exportar — Descarga un CSV con los journeys visibles (respetando filtros activos).
    • Analizar (requiere selección de 1) — Abre la vista de análisis detallado del journey.
    • Data Extensions — Escanea las DEs de entrada de todos los journeys filtrados y las muestra agrupadas.
    • Comunicaciones (requiere selección) — Carga las comunicaciones (emails, SMS, etc.) configuradas en los journeys seleccionados y las muestra como columnas adicionales.
    • Copiar (requiere selección de 1) — Abre el asistente de clonación del journey.
    • Acciones (requiere selección) — Permite Pausar, Reanudar, Parar o Borrar los journeys seleccionados.
    • Ver Errores (requiere selección de 1) — Navega a la vista de errores de ese journey.

    Al pulsar Parar se muestra un modal con dos opciones: parar solo la versión activa (Current) o parar todas las versiones. Para los journeys de tipo Multistep, al borrarlos se para primero todas las versiones automáticamente.

  • Clonador de Journeys

    Accesible desde la vista de Journeys seleccionando uno y pulsando Copiar. El asistente guía el proceso según el tipo de entrada del journey original:

    • EmailAudience — Pregunta si se quiere clonar la Data Extension de entrada o reutilizar una existente. Si se clona, se puede indicar el nombre de la nueva DE.
    • AutomationAudience — Busca las DEs de destino del automatismo de origen y permite seleccionar cuál actuará como fuente de datos del nuevo journey.

    En todos los casos se puede modificar el nombre del nuevo journey antes de ejecutar la clonación. El proceso crea el event definition, la DE (si aplica) y el propio journey con toda su configuración.

  • Errores de Journeys

    Vista accesible desde el botón Ver Errores en la tabla de Journeys (con un journey seleccionado). Muestra todos los errores registrados en ese journey en un rango de fechas configurable.

    Permite filtrar por: Journey, Estado del error, Actividad y Tipo de error. Los resultados son paginados y se pueden exportar en CSV con el botón Exportar.

Clonar Queries

  • Clonador Masivo de Queries

    Esta funcionalidad permite clonar de forma masiva todas las Query Activities de una carpeta de origen a una carpeta de destino, clonando también sus Data Extensions de destino.

    El proceso es un asistente de 2 pasos:

    • Paso 1 — Configuración de carpetas: Se indican los nombres (o parte del nombre) de tres carpetas: la carpeta origen de las queries, la carpeta destino para las queries clonadas y la carpeta destino para las DEs clonadas. Al pulsar Buscar Carpetas se muestran las carpetas encontradas en tres columnas; se debe seleccionar una de cada columna y pulsar Continuar.
    • Paso 2 — Selección de queries: Se muestra la lista de todas las queries de la carpeta origen. Para cada una se puede editar el nombre de la query clonada y el nombre de la DE clonada. Se puede seleccionar todas con el checkbox del encabezado o marcarlas individualmente. Al pulsar Clonar Seleccionadas se lanza el proceso.

    Si varias queries comparten la misma DE de destino, esta solo se clona una vez y se reutiliza para las demás.

Cloud Pages

  • Gestión de Cloud Pages

    Esta vista muestra todas las Cloud Pages de la instancia en una tabla paginada con: Nombre, Tipo, Fecha de Modificación, Fecha de Publicación, Ubicación, URL y Page ID.

    Filtros disponibles: por nombre, por Page ID, por contenido (si se han cargado los contenidos) y por tipo.

    Botones disponibles:

    • Refrescar — Recarga la lista de Cloud Pages desde la API.
    • Exportar — Descarga un CSV con las Cloud Pages visibles.
    • Recuperar IDs — Abre un modal con instrucciones para obtener los Page IDs de las Cloud Pages. Es necesario abrir la URL indicada en el navegador (con sesión activa de MC) y pegar el JSON resultante. Esto permite que la columna Page ID de la tabla se rellene correctamente.
    • Recuperar Contenidos — Abre un modal con las instrucciones para extraer el HTML de todas las Cloud Pages. Hay que abrir Content Builder en el navegador, ejecutar el script en la consola (F12), copiar el resultado y pegarlo en el modal. Una vez importados, el filtro de contenido de la tabla queda activo. Nota: Si al abrir el enlace se muestra UNAUTHORIZED, abre Content Builder y vuelve a intentarlo.

Gestión de Envíos

  • Gestión de Envíos

    Esta vista agrupa toda la configuración de envío de Marketing Cloud en tres pestañas:

    • Send Classifications — Lista todas las clasificaciones de envío de la instancia. Muestra el nombre, External Key, tipo (Comercial/Transaccional), el Sender Profile y Delivery Profile asociados y la fecha de modificación. Permite filtrar por nombre/key, por perfil y por tipo.
    • Sender Profiles — Lista todos los perfiles de remitente. Muestra nombre, External Key, From Name, From Email, si tiene Auto-Reply, si tiene reenvío automático (Forward To) y la fecha de modificación. Permite filtrar por nombre/key, From Name y From Email.
    • Delivery Profiles — Lista los perfiles de entrega de la instancia. Muestra nombre, External Key, descripción, modo IP, dirección IP, header y footer. Dado que la API de MC no expone estos datos directamente, se obtienen ejecutando un script en la consola del navegador en la página de Delivery Profiles. El modal explica los pasos y proporciona el script a copiar.

    Los botones Refrescar y Exportar son globales: refrescan o exportan la pestaña activa en ese momento. La exportación genera un CSV con los datos visibles respetando los filtros activos.

    Las columnas de todas las tablas son ordenables haciendo clic en la cabecera.

Usuarios

  • Gestión de Usuarios y Permisos

    Esta vista tiene dos pestañas:

    • Lista de Usuarios — Muestra todos los usuarios de la instancia con: Nombre (ID), UserName, si es API User, Último Login, Estado (activo/inactivo) y Roles asignados. Permite filtrar por nombre, por estado (activos/inactivos) y por roles (selector múltiple desplegable). Las columnas son ordenables. El botón Descargar Usuarios exporta en CSV los usuarios visibles.
    • Detalle / Comparativa — Permite obtener un desglose completo de permisos por usuario para comparar entre ellos. Como MC no expone esta información por API, es necesario ejecutar un script en la consola del navegador (F12) desde la página de administración de usuarios. El modal de Preparar Captura proporciona el enlace y el script a ejecutar. Una vez pegado el resultado, se genera una tabla expandible con todos los permisos agrupados por categoría. El botón Solo Diferencias oculta los permisos iguales entre usuarios para facilitar la comparativa. El botón Colapsar Todo / Expandir Todo controla la visibilidad de los grupos de permisos.

Generador ERD

  • Generador de Diagramas Entidad-Relación (ERD)

    Esta funcionalidad genera un diagrama visual de las relaciones entre Data Extensions de un Attribute Group de Contact Builder. Es útil para entender el modelo de datos del cliente de un vistazo.

    El proceso tiene dos pasos (pestañas):

    • 1. Extraer JSON — Hay que abrir el enlace que proporciona la app (apunta a la API interna de Attribute Groups de MC) y ejecutar el script en la consola del navegador. El script muestra un popup donde seleccionar qué Attribute Group analizar y genera el JSON de las relaciones.
    • 2. Generar Diagrama — Se pega el JSON extraído en el cuadro de texto y se pulsa Generar Diagrama. Opcionalmente se puede marcar Ocultar tabla Contacts para simplificar el diagrama (la tabla Contacts se marca con 🔑 en los campos que la referencian).

    El diagrama resultante es interactivo:

    • Las tablas son arrastrables para reorganizar el layout.
    • Al hacer clic en un campo se resalta la relación correspondiente (líneas de FK/REF).
    • Los campos se colorean según su tipo: 🟠 PK, 🟢 FK, 🟣 REF.
    • Al pasar el ratón sobre un campo se muestra un tooltip con el tipo de dato y la relación.
    • Se puede descargar el diagrama como imagen (Descargar Imagen) o exportar las relaciones como CSV (Descargar CSV).
    • El botón Nuevo Diagrama limpia el lienzo para empezar con otro Attribute Group.

Auditoría

  • Auditoría de Instancia

    Esta vista realiza un análisis completo del estado de la instancia de Marketing Cloud y genera un dashboard con KPIs y gráficos para cada área. Si ya existe una auditoría guardada para el cliente activo, se carga automáticamente al entrar a la vista.

    El análisis se organiza en seis pestañas de resultados: Usuarios, Automatismos, Journeys, Cloud Pages, Send Management y Data Extensions.

    Antes de lanzar el escaneo se pueden activar opciones de análisis profundo:

    • Automatismos — Análisis Profundo (lento: 2 llamadas por automatismo + 1 por SQL/SSJS) — Detecta email de alerta por error, extrae dominios de aviso, detecta descripciones en SQL/SSJS y genera un mapa de actividades compartidas entre automatismos.
    • Journeys — Análisis Profundo (rápido si la API devuelve actividades en la llamada de lista) — Detecta nodos Salesforce activos, calcula el mix multicanal real (Email, SMS, Push/In-App, WhatsApp) e identifica journeys con solo lógica (sin envíos).
    • Data Extensions — Análisis desde JSON — Para auditar las DEs hay que ejecutar un script en la consola del navegador estando en Contact Builder. El script recorre todas las carpetas (puede tardar ~20 min para ~6.000 DEs) y genera un JSON que se pega en la vista. Las DEs de la carpeta Shared se excluyen automáticamente. Atención: Cada escaneo sobreescribe la caché anterior.

    Métricas disponibles por área:

    • Usuarios: total, activos, inactivos, API users, último login, roles más frecuentes.
    • Automatismos: total, activos/programados, sin historial de ejecución, que lanzan Journeys, actividades de import/export, nombres de prueba.
    • Journeys: total, publicados, por tipo/subtipo/estado, integración con Salesforce, mix de canales, con/sin Goals, con/sin criterios de salida, inactividad.
    • Cloud Pages: total, por tipo, publicadas vs no publicadas.
    • Send Management: Send Classifications, Sender Profiles, perfiles en uso vs huérfanos, remitentes dinámicos, AutoReply y Forward.
    • Data Extensions: total, sin descripción (por propietario), sendable/testable, con retención, vacías, con nombre de prueba, carpetas con más de 15 DEs.

    Haciendo clic en cualquier barra de los gráficos se abre un modal de detalle con la lista de elementos que componen esa métrica, exportable en CSV.

    Una vez completada la auditoría están disponibles dos botones:

    • Descargar PDF — Genera un informe PDF con todos los gráficos y KPIs.
    • Exportar Detalles — Descarga un ZIP con un CSV por cada categoría auditada.

    Los resultados se guardan automáticamente en disco para el cliente activo y se cargan la próxima vez que se acceda a la vista. El botón Volver a Opciones permite relanzar el escaneo con diferentes opciones (sobreescribiendo la caché anterior).
