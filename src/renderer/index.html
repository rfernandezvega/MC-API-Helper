Auditoría de Instancia

Auditoría: usuarios, automatismos, journeys, cloud pages, configuración de envío, data extensions y contenidos.

Cómo lanzar la auditoría

  1. Para que la pestaña Contenidos tenga datos, entra antes a la vista de Contenidos y pulsa Refrescar (la auditoría reutiliza esa caché, no descarga contenidos).
  2. Para auditar Data Extensions (opcional), copia el script de abajo, ejecútalo en la consola de Contact Builder y pega el JSON resultante en el cuadro.
  3. Pulsa «Iniciar Escaneo de Instancia» (arriba a la derecha) y confirma. No cierres la aplicación mientras dura el proceso.
  4. Al terminar, revisa las pestañas del panel y descarga el Informe (PDF) o los Detalles.

Los Journeys se descargan durante el escaneo y quedan en una caché compartida con las vistas de Journeys y Contenidos: si ya están descargados (misma versión), se reutilizan y solo se bajan los nuevos o modificados. En cualquier caso, siempre se muestran el total de llamadas API y el tiempo del escaneo. Hay un límite anual de llamadas API: como referencia, un cliente con 700 Journeys y 200 automatismos puede tardar unos 10 minutos.

Si ya existe una auditoría guardada para este cliente, se cargará automáticamente al entrar a esta vista.

Qué se analiza en cada pestaña

Pestaña Descripción Origen del dato
Usuarios Roles, estados (activo/bloqueado), tipo de usuario y último acceso. Se descarga durante el escaneo (no depende de otra vista).
Automatismos Tipos de actividad, estados, programación, email de alerta por error, descripciones en SQL/SSJS y actividades compartidas. Se descarga durante el escaneo (no depende de otra vista).
Journeys Estado, subtipo, Goals/salidas, actividad reciente, mix multicanal (Email/SMS/Push/WhatsApp) y nodos Salesforce. Caché compartida con la vista de Journeys (y de Contenidos). Se descarga aquí si falta.
Cloud Pages Cantidad, tipo y estado de publicación de las páginas. Se descarga durante el escaneo (no depende de otra vista).
Send Management Send Classifications, Sender/Delivery Profiles y configuración de envío. Se descarga durante el escaneo (no depende de otra vista).
Data Extensions Volumetría, campos, retención y uso de las DEs. JSON pegado del script de abajo (Contact Builder). No consume llamadas de la app.
Contenidos Contenidos por tipo, plantillas inexistentes, bloques/plantillas sin uso y comunicaciones dentro/fuera de journeys. Caché de la vista de Contenidos (refréscala antes) + caché de Journeys. No consume llamadas aquí.

Primeros pasos

						
Para usar la app necesitas: (1) crear un paquete API en Marketing Cloud, (2) configurar ese paquete como cliente dentro de la app y (3) iniciar sesión. Una vez con sesión iniciada en un cliente, todas las vistas quedan disponibles.


						
Paso 1 · Crear el paquete API en Marketing Cloud

						
    
							
  • Crea el paquete siempre en la BU PADRE. Si vas a usarlo en otras BUs, da permiso a cada BU y crea una conexión por cada una.
    • 
							
  • Ve a Setup → Apps → Installed Packages y crea un paquete de tipo Web App llamado MC API Helper.
    • 
							
  • En Redirect URI pon: https://127.0.0.1:8443/callback
    • 
							
  • Asigna estos permisos (pestaña del componente del paquete):
								
      
									
    • Email: Read, Write
      • 
									
    • Automations: Read, Write, Execute
      • 
									
    • Journeys: Read, Write, Activate/Stop/Pause/Resume/Send/Schedule, Delete
      • 
									
    • Audiences: Read, Write
      • 
									
    • List and Subscribers: Read, Write
      • 
									
    • Data Extensions: Read, Write
      • 
									
    • Documents and Images: Read
      • 
									
    • Saved Content: Read
      • 
									
    • File Locations: Read
      • 
									
    • Users: Read
      • 
									
    • Accounts: Read
      • 
								
    
							
    • 
							
  • En la pestaña ACCESS del paquete, da permiso a los usuarios que vayan a usar la app.
    • 
						


						
Paso 2 · Configurar el cliente en la app

						
    
							
  • Ve a Configuración de APIs e introduce los datos del paquete (Client Id, Client Secret, Auth URI, etc.).
    • 
							
  • Opcional: configura las DEs de Búsqueda de Clientes antes del login para que se guarden automáticamente (ver la vista Configuración de APIs).
    • 
						


						
Paso 3 · Iniciar sesión

						
    
							
  • Pulsa Login: se abrirá una ventana con el login de Marketing Cloud; introduce tus credenciales.
    • 
							
  • Si falla puntualmente, reinténtalo (a veces MC no gestiona bien la primera conexión). Si persiste, revisa que tu usuario tiene permiso en el paquete del Paso 1.
    • 
							
  • Una vez autenticado, selecciona el cliente en el desplegable superior para trabajar con él.
    • 
						


						
Cada vista tiene normalmente un botón Refrescar que descarga datos por API y los guarda en una caché local del cliente. Al volver a entrar verás lo cacheado; pulsa Refrescar para actualizar.

					

				


				
				

					

						
Generalidades de la app

						
Funciones comunes disponibles en toda la aplicación.


						
Selector de cliente

						
    
							
  • En la cabecera superior eliges el cliente con el que trabajar. Todas las vistas usan ese cliente y su caché local.
    • 
						


						
Buscador de texto en la ventana

						
    
							
  • Permite buscar y navegar por el texto visible de la vista actual, como el buscador del navegador.
    • 
						


						
Panel de logs (lateral derecho)

						
    
							
  • Registra todas las acciones y llamadas a la API. Pulsa los iconos < / > para mostrar u ocultar el panel.
    • 
							
  • Tres apartados: Mensajes (qué se está haciendo), Petición (llamadas a la API) y Respuesta (lo que devuelve la API).
    • 
							
  • Desde Log de Eventos puedes descargar los logs con fecha. Útil para revisar qué llamadas se hicieron si algo da error.
    • 
						


						
Novedades

						
    
							
  • El menú principal incluye un panel de Novedades con el historial de versiones y los cambios de cada una.
    • 
						

						
La app comprueba si hay una versión nueva al arrancar; si la hay, la descarga y avisa con la opción de instalar.

					

				


				
				

					

						
Configuración de APIs

						
Aquí se dan de alta y gestionan los clientes (credenciales del paquete API) y se inicia sesión.


						
Qué se puede hacer

						
    
							
  • Dar de alta un cliente con los datos del paquete (Client Id, Client Secret, Auth/REST/SOAP URI, MID/Business Unit, etc.).
    • 
							
  • Login — Inicia el flujo de autenticación por navegador contra Marketing Cloud.
    • 
							
  • Logout — Cierra la sesión del cliente y borra las credenciales seguras guardadas; también limpia las cachés locales de ese cliente.
    • 
						


						
Pestaña "DEs de Búsqueda de Clientes"

						
    
							
  • Define una serie de Data Extensions sobre las que poder consultar la ficha de un cliente desde Buscadores → Clientes (qué comunicaciones ha recibido, estado en tablas, exclusiones, etc.) sin lanzar queries.
    • 
							
  • Por cada tabla se indica: Nombre de la DE, External Key y el campo por el que buscar al cliente (el que coincide con el identificador).
    • 
							
  • Si las configuras antes del login se guardan automáticamente. Si las añades después, pulsa el botón de guardar de la parte superior.
    • 
							
  • Se pueden exportar/importar para que otra persona del equipo no tenga que configurarlas a mano.
    • 
						

					

				


				
				

					

						
Buscadores

						
Conjunto de buscadores para localizar dónde se usa o qué contiene cada elemento de la instancia.

						
Todas las tablas de resultados tienen encima un botón Descargar que exporta lo encontrado a CSV (se habilita al haber resultados). El fichero se genera con separador ;, todas las celdas entrecomilladas y BOM UTF-8: los saltos de línea, tabuladores y comillas del texto de queries y scripts se sanean para que el fichero se abra bien en Excel. En las tablas paginadas se exportan todos los registros, no solo la página visible, y se respeta la ordenación aplicada.


						
Buscador de Data Extensions

						
    
							
  • Busca una DE por Nombre o External Key; devuelve todas las que contengan un texto similar.
    • 
						


						
Buscador de Orígenes de datos

						
    
							
  • Indica qué query o import inserta/actualiza datos en una DE, mostrando en qué automatismo y paso se encuentra.
    • 
							
  • El check Mostrar Descripción / Query oculta o muestra la columna con la query o la descripción del import.
    • 
							
  • Solo se listan las queries activas: las que están en estado Inactive (borradas lógicamente en Marketing Cloud) se descartan.
    • 
						


						
Buscador de Clientes

						
    
							
  • Vista rápida de un cliente: busca su información en las DEs configuradas en Configuración de APIs → DEs de Búsqueda de Clientes (selecciona la tabla y muestra sus campos filtrados por el cliente).
    • 
							
  • Muestra en qué Journeys está el contacto en ese momento y permite expulsarlo de uno o varios journeys a la vez (selección múltiple).
    • 
							
  • Cada tabla tiene su propia descarga en CSV: resultados del cliente, journeys, audiencia de WhatsApp y cada Data Extension consultada.
    • 
						


						
Buscador de Texto en Queries

						
    
							
  • Busca una cadena de texto en todas las queries; muestra la query (con enlace) y en qué automatismos y pasos aparece. La columna con la query se puede mostrar/ocultar.
    • 
							
  • Solo se muestran las queries activas: las que están en estado Inactive (borradas lógicamente en Marketing Cloud) no aparecen en los resultados.
    • 
						


						
Buscador de Texto en Scripts

						
    
							
  • Busca una cadena de texto en los scripts; muestra el script encontrado con su enlace.
    • 
						


						
Buscador de Contenidos

						
    
							
  • Busca cualquier contenido de Content Builder por nombre o id; muestra la tipología y la ruta. Desde el detalle se puede ver y descargar el código.
    • 
						


						
Buscador de Actividades

						
    
							
  • Busca actividades de Automation Studio (queries, scripts, extracts, imports, file transfers…) por nombre o External Key (exactos). Útil para saber en qué automatismos se usa una actividad antes de modificarla o borrarla.
    • 
						

					

				


				
				

					

						
Contenidos

						
Descarga y cachea todos los contenidos de Content Builder para poder explorarlos, buscarlos, analizar su uso y borrarlos, sin entrar a Marketing Cloud. Los datos se obtienen por API (ya no hace falta ejecutar scripts en consola).


						
Pestañas

						
    
							
  • Emails, Plantillas, Push, SMS, Whatsapp, Plantillas WA, Bloques y Code Snippet. Cada pestaña muestra un contador de elementos.
    • 
							
  • Junto al total se muestra la fecha de la caché de contenidos y la fecha de la caché de Journeys (esta última la genera la vista de Journeys y sirve para el filtro de uso).
    • 
						


						
Botones de cabecera

						
    
							
  • Refrescar — Descarga los contenidos por API (puedes elegir qué tipos) y sobrescribe la caché local del cliente.
    • 
							
  • Exportar — Descarga un CSV de la pestaña activa (respeta los filtros).
    • 
							
  • Borrar (rojo) — Elimina los contenidos seleccionados. Pide confirmación indicando cuántos se van a borrar, llama al DELETE de la API y descarga un CSV con los eliminados. No permite borrar contenidos que estén en uso (el botón se deshabilita si algún seleccionado está en uso).
    • 
						


						
Filtros

						
    
							
  • Buscador — Filtra por nombre, id y también por el cuerpo del contenido (HTML, asunto, preheader, variables/botones de WhatsApp, contenido resuelto…). Útil, por ejemplo, para saber qué emails usan una plantilla buscando su nombre.
    • 
							
  • Uso (Todos / En uso / Sin uso) — Clasifica: emails, push, SMS y WhatsApp según los Journeys cacheados; bloques, plantillas y snippets según su cadena de referencias (qué los usa). Sin caché de Journeys, los mensajes no se pueden clasificar.
    • 
							
  • Plantilla inexistente — Muestra solo los emails cuya plantilla ya no existe en la pestaña de Plantillas.
    • 
							
  • Filtro de fecha — Selecciona el campo (Modificado/Creado) y un rango Desde/Hasta.
    • 
						


						
Selección y acciones por fila

						
    
							
  • Haz clic en una fila para seleccionarla (uno o varios) de cara al borrado.
    • 
							
  • Iconos por fila: ver código, ver código resuelto (emails, ensambla bloques referenciados), dónde se usa (bloques/plantillas referenciados por otros contenidos), Journeys donde se usa (emails/push/SMS/WhatsApp: abre un panel con los Journeys que lo utilizan) y analizar en Buscadores.
    • 
						

						
El emparejamiento "en uso" de emails con Journeys se hace por el id legacy del email; requiere haber refrescado contenidos y haber cacheado los Journeys.

					

				


				
				

					

						
Cloud Pages

						
Lista todas las Cloud Pages de la instancia en una tabla paginada con: Nombre, Tipo, Fecha de Modificación, Fecha de Publicación, Modificado por, Ubicación, URL y Page ID. La cabecera de la tabla queda fija al hacer scroll.


						
Botones de cabecera

						
    
							
  • Refrescar — Recarga la lista (y el contenido) de Cloud Pages por API.
    • 
							
  • Exportar — Descarga un CSV con las Cloud Pages visibles (respeta filtros).
    • 
							
  • Recuperar IDs — Abre un modal con instrucciones: hay que abrir un enlace a la API interna en el navegador (con sesión MC activa) y pegar el JSON resultante para rellenar la columna Page ID/URL.
    • 
						


						
Filtros

						
    
							
  • Por nombre, por Page ID, por contenido, por tipo, por publicación (publicadas / no publicadas), por URL (con/sin URL) y por rango de fechas (Fecha Modificación / Fecha Publicación + Desde/Hasta).
    • 
						


						
Columna de acción y detalle

						
    
							
  • Cada fila tiene un icono que abre un panel lateral (drawer) con las dependencias de la Cloud Page (DEs referenciadas, parámetros, atributos, Content Blocks, Triggered Sends, URLs de HTTP.Post y redirecciones) y el código fuente con resaltado.
    • 
							
  • Desde el drawer se puede descargar el código de la página.
    • 
						

					

				


				
				
				

					

						
Journeys

						
Tabla paginada con todos los journeys: Nombre, Versión, Fecha creación/modificación/actividad, Tipo, Subtipo, Estado, Data Extension de entrada y DEs usadas en actividades. La cabecera queda fija al hacer scroll. Junto al título se muestra la fecha de la caché de comunicaciones.


						
Botones de cabecera

						
    
							
  • Refrescar — Recarga la lista de journeys por API.
    • 
							
  • Exportar — Descarga un CSV con los journeys visibles (respeta filtros).
    • 
							
  • Analizar (1 seleccionado) — Abre el análisis detallado del journey.
    • 
							
  • Data Extensions — Escanea las DEs usadas en las actividades de los journeys filtrados y las muestra en su columna.
    • 
							
  • Descargar detalle — Descarga el journey completo (actividades + comunicaciones) y lo cachea. Permite elegir todos o solo los seleccionados. Esta caché alimenta el filtro de uso de la vista de Contenidos y se sobrescribe con la última descarga.
    • 
							
  • Copiar (1 seleccionado) — Abre el asistente de clonación del journey.
    • 
							
  • Acciones (selección) — Permite Pausar, Reanudar, Parar o Borrar los journeys seleccionados.
    • 
							
  • Ver Errores (1 seleccionado) — Abre la vista de errores de ese journey.
    • 
						


						
Filtros

						
    
							
  • Por nombre, tipo, subtipo, estado, Data Extension de entrada y campos en entrada (uno o varios separados por , ; |).
    • 
							
  • Comunicaciones — Botón que filtra para mostrar solo los journeys que tienen comunicaciones reales cacheadas.
    • 
							
  • Filtro de fecha — Campo (creación / modificación / actividad) + rango Desde/Hasta.
    • 
						


						
Columna de comunicaciones

						
    
							
  • Los journeys con comunicaciones muestran un icono que abre un panel lateral con sus emails (con datos del Triggered Send: envíos, en cola, errores…), SMS, Push y WhatsApp.
    • 
						


						
Acciones y clonación

						
    
							
  • Al Parar se elige entre parar solo la versión activa o todas las versiones. Para journeys Multistep, al borrarlos se paran antes todas las versiones automáticamente.
    • 
							
  • Clonador: para entrada EmailAudience pregunta si clonar la DE de entrada o reutilizar una existente; para AutomationAudience permite elegir la DE de destino del automatismo origen como fuente. En ambos casos se puede cambiar el nombre del nuevo journey.
    • 
							
  • Errores de Journeys: muestra los errores de un journey en un rango de fechas, con filtros por journey, estado, actividad y tipo, y exportación a CSV.
    • 
						

					

				


				
				

					

						
Automatismos

						
Tabla paginada con todos los automatismos: Nombre, Última Ejecución, Próxima Ejecución, Estado, si lanza Journey y, si se cargan, las notificaciones de error/ejecución. Las columnas son ordenables. Los automatismos de sistema (los que empiezan por el MID) se ocultan automáticamente.


						
Botones de cabecera

						
    
							
  • Refrescar — Recarga los datos por API.
    • 
							
  • Calendario — Abre un panel lateral con un calendario que sitúa los automatismos actualmente filtrados en la vista por su próxima fecha de ejecución. Los días con algo programado se marcan en azul; al pulsar un día, el panel derecho muestra qué automatismos hay y a qué hora. Se puede cambiar el Año.
    • 
							
  • Analizar (1 seleccionado) — Abre el análisis detallado del automatismo.
    • 
							
  • Cargar Notificaciones — Obtiene los emails de alerta configurados y muestra las columnas de notificación.
    • 
							
  • Exportar — Descarga un CSV con los datos visibles (respeta filtros).
    • 
							
  • Acciones (selección) — Modal para Activar, Ejecutar o Parar; cada acción solo se habilita si el estado de lo seleccionado es compatible.
    • 
							
  • Clonar (1 seleccionado) — Abre el clonador selectivo del automatismo.
    • 
						


						
Filtros

						
    
							
  • Por nombre (uno o varios separados por , ; |), por estado y por lanza Journey.
    • 
							
  • Filtro de fecha — Campo (Última / Próxima Ejecución) + rango Desde/Hasta.
    • 
							
  • Filtro por notificación — Aparece solo tras pulsar Cargar Notificaciones; filtra los automatismos por el texto de las columnas de notificación de error/ejecución.
    • 
						


						
Clonador de Automatismos

						
    
							
  • Permite duplicar un automatismo de forma selectiva: por cada actividad se elige si clonarla o reutilizar la original, y se puede cambiar su nombre y su DE de destino.
    • 
							
  • Se puede fijar el Nombre destino, la Carpeta destino y una carpeta de DEs por defecto para no configurarlas una a una. El proceso crea primero las DEs, luego las actividades y por último el automatismo.
    • 
						

					

				


				
				

					

						
Data Extensions (Gestión unificada)

						
Vista con tres pestañas para crear DEs, configurar sus campos y recuperar/documentar DEs existentes.


						
Creación de Data Extensions

						
    
							
  • Se indica Nombre, Descripción (obligatoria) y si es Sendable (requiere haber configurado los campos para elegir el que relaciona con el suscriptor).
    • 
							
  • Buscador de carpeta de destino.
    • 
							
  • Crear Data Extension — Crea la DE con los campos configurados. No se limpia la configuración tras crearla (para seguir creando DEs similares).
    • 
						


						
Configuración de Campos

						
    
							
  • Importar un listado de campos (p. ej. copiados del modelo de datos de Salesforce) indicando el separador.
    • 
							
  • Crear/actualizar campos, crear campos de ejemplo de cada tipo, limpiar la tabla, añadir/eliminar filas y ordenar filas con las flechas (útil para copiar una DE manteniendo los identificadores al principio; no se puede reordenar sobre una DE existente).
    • 
						


						
Recuperar y borrar campos / Documentar

						
    
							
  • Recuperar Campos — Indica la External Key y recupera los campos de una DE existente (para copiarla o borrar campos que no se pueden borrar por pantalla).
    • 
							
  • Borrar Campo — Borra el campo seleccionado de la lista.
    • 
							
  • Documentar DEs — Genera un CSV con la estructura completa de todas las DEs de una carpeta (útil, p. ej., para documentar las Synchronized DEs y compararlas con el modelo de Salesforce).
    • 
						

					

				


				
				

					

						
Crear Carpetas

						
Crea de golpe una estructura de carpetas para Data Extensions, Queries, Journeys, Automatismos, Contenidos o Scripts. Útil en clientes con campañas repetitivas.


						
Cómo se usa

						
    
							
  • Indica la carpeta principal bajo la que se crearán las demás (con el buscador de carpetas seleccionas cuál usar).
    • 
							
  • Escribe el nombre de cada carpeta en líneas distintas; para que una sea hija de otra, sángrala con doble espacio o tabulador.
    • 
						

					

				


				
				

					

						
Clonar Queries

						
Clona de forma masiva todas las Query Activities de una carpeta a otra, clonando también sus Data Extensions de destino. Asistente de 2 pasos.


						
Paso 1 · Carpetas

						
    
							
  • Indica el nombre (o parte) de tres carpetas: origen de las queries, destino de las queries clonadas y destino de las DEs clonadas.
    • 
							
  • Buscar Carpetas muestra las coincidencias en tres columnas; selecciona una de cada y pulsa Continuar.
    • 
						


						
Paso 2 · Selección de queries

						
    
							
  • Lista todas las queries de la carpeta origen. Por cada una puedes editar el nombre de la query y de la DE clonadas.
    • 
							
  • Selecciona todas (checkbox de cabecera) o individualmente y pulsa Clonar Seleccionadas.
    • 
							
  • Si varias queries comparten la misma DE de destino, esta se clona una sola vez y se reutiliza.
    • 
						

					

				


				
				

					

						
Gestión de Envíos

						
Agrupa la configuración de envío en tres pestañas. Los botones Refrescar y Exportar son globales y actúan sobre la pestaña activa (la exportación respeta los filtros). Todas las columnas son ordenables.


						
Send Classifications

						
    
							
  • Clasificaciones de envío: nombre, External Key, tipo (Comercial/Transaccional), Sender Profile y Delivery Profile asociados y fecha de modificación. Filtros por nombre/key, por perfil y por tipo.
    • 
						


						
Sender Profiles

						
    
							
  • Perfiles de remitente: nombre, External Key, From Name, From Email, Auto-Reply, Forward To y fecha de modificación. Filtros por nombre/key, From Name y From Email.
    • 
						


						
Delivery Profiles

						
    
							
  • Perfiles de entrega: nombre, External Key, descripción, modo IP, IP, header y footer.
    • 
							
  • Como la API de MC no expone estos datos, se obtienen ejecutando un script en la consola del navegador (F12) en la página de Delivery Profiles; el modal explica los pasos y proporciona el script.
    • 
						

					

				


				
				

					

						
Usuarios

						
Dos pestañas: la lista de usuarios y el detalle/comparativa de permisos.


						
Lista de Usuarios

						
    
							
  • Muestra Nombre (ID), UserName, si es API User, Último Login, Estado (activo/inactivo) y Roles. Columnas ordenables.
    • 
							
  • Filtros por nombre, por estado y por roles (selector múltiple).
    • 
							
  • Descargar Usuarios — Exporta en CSV los usuarios visibles.
    • 
						


						
Detalle / Comparativa

						
    
							
  • Desglose completo de permisos por usuario para comparar entre ellos. Como MC no lo expone por API, hay que ejecutar un script en la consola (F12) desde la administración de usuarios; el modal Preparar Captura da el enlace y el script.
    • 
							
  • Una vez pegado el resultado, se genera una tabla expandible con los permisos por categoría.
    • 
							
  • Solo Diferencias — Oculta los permisos iguales entre usuarios. Colapsar/Expandir Todo — Controla la visibilidad de los grupos.
    • 
						

					

				


				
				

					

						
Validar Emails

						
Valida direcciones de email contra las mismas comprobaciones que usa Marketing Cloud:

						
    
							
  • SyntaxValidator — Sintaxis de la dirección.
    • 
							
  • MXValidator — Existencia de registros MX del dominio.
    • 
							
  • ListDetectiveValidator — Listas de detección de MC.
    • 
						

						
Introduce el email y se indica si es válido o qué validación falla.

					

				


				
				

					

						
Generador ERD

						
Genera un diagrama entidad-relación de las Data Extensions de un Grupo de Atributos de Contact Builder. Los datos se obtienen directamente por API (ya no hay que ejecutar scripts ni pegar JSON).


						
Cómo se usa

						
    
							
  • Al entrar, la app carga los grupos de atributos por API y los lista por nombre (indicando si son de Sistema o de Usuario y cuántas entidades tienen).
    • 
							
  • Buscar — Filtra la lista de grupos por nombre. Ocultar grupos de sistema — Deja solo los de usuario. Refrescar — Vuelve a cargar los grupos por API.
    • 
							
  • Ocultar tabla Contacts — Si se marca, no se dibuja la tabla central Contacts (los campos que la referencian se marcan con 🔑).
    • 
							
  • Selecciona un grupo y pulsa Generar ERD para dibujar su diagrama con todas sus entidades y relaciones.
    • 
						


						
Diagrama

						
    
							
  • Las tablas son arrastrables para reorganizar el layout.
    • 
							
  • Clic en un campo: resalta su relación (líneas FK/REF). Colores: 🟠 PK, 🟢 FK, 🟣 REF. Al pasar el ratón se muestra un tooltip con el tipo de dato y la relación.
    • 
							
  • Descargar Imagen — Exporta el diagrama como PNG. Descargar CSV — Exporta las relaciones. Nuevo Diagrama — Vuelve a la selección de grupo.
    • 
						

					

				


				
				

					

						
Auditoría de Instancia

						
Analiza el estado de la instancia y genera un dashboard con KPIs y gráficos por área. Si ya hay una auditoría guardada del cliente, se carga al entrar.


						
Áreas analizadas

						
    
							
  • Seis pestañas de resultados: Usuarios, Automatismos, Journeys, Cloud Pages, Send Management y Data Extensions.
    • 
						


						
Opciones de análisis profundo (antes de escanear)

						
    
							
  • Automatismos — Análisis Profundo (lento) — Email de alerta por error, dominios de aviso, descripciones en SQL/SSJS y mapa de actividades compartidas.
    • 
							
  • Journeys — Análisis Profundo — Nodos Salesforce, mix multicanal real (Email/SMS/Push/WhatsApp) y journeys solo de lógica.
    • 
							
  • Data Extensions — Análisis desde JSON — Requiere ejecutar un script en la consola (F12) en Contact Builder; recorre todas las carpetas (puede tardar ~20 min en miles de DEs) y se pega el JSON. Las DEs de la carpeta Shared se excluyen. Cada escaneo sobrescribe la caché anterior.
    • 
						


						
Resultados y exportación

						
    
							
  • Cada barra de los gráficos abre un modal de detalle con la lista de elementos, exportable en CSV.
    • 
							
  • Descargar PDF — Informe con gráficos y KPIs. Exportar Detalles — ZIP con un CSV por categoría. Volver a Opciones — Relanza el escaneo con otras opciones.
    • 
						

						
Los resultados se guardan en disco para el cliente activo y se cargan la próxima vez.
